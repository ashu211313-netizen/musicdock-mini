# 同期遅延の修正 — 2.0.3

画像では極小PiPに曲情報と再生ボタンが表示され、「再生情報の同期を確認中…」が残っていた。画像だけでは実セッションのメディア状態は確定できないため、実機原因を断定しない。

コード監査で確認できた問題:
- 初期整合に600ms、曲操作後に750msの待機があり、さらに300msポーリング境界が重なる。
- 一時的に再生バーと音声の時刻がずれると待機開始時刻をリセットしていた。
- ジャケットURLを曲IDに含めており、画像の差し替えを曲変更として扱った。
- 極小表示ではステータスが出るたびに時間・シーク全体を非表示にしていた。

対応:
- 安定確認200ms、曲操作後150msへ短縮。イベントを50msに集約して反映し、250msポーリングを復旧用として維持。
- 不一致中の操作を無効にしたまま、同じ候補の待機開始時刻を保持。候補・曲・リソースが変われば新しい安定確認が必要。
- ジャケットを識別子から除外。再生バーのタイトルリンクに動画IDがあればそれを使用。動画IDがない場合は曲名とアーティストの組合せを維持する。
- 最新リモートのグリッドレイアウトと幾何学テストを取り込み、極小ステータスをアーティスト欄に表示。時間・シークバーは隠さない。
- 小窓を閉じるとMutationObserver、メディアイベント、タイマーを解除する。

数値の200/150/50msは実装の設定値であり、実YouTube Musicのエンドツーエンド実測値ではない。別曲、古いメディア、複数候補、再生バーとメディアの不一致では引き続き操作を拒否する。

型チェック、単体35件（遅延・画像更新・同名別動画・イベント解除を追加）、Playwright6件で検証。Windows Chromeで本番レンダラーを描画。500×80 / 500×66 / 320×57 / 244×57を含む小型ウィンドウの重なりとスクロール、同期中のシーク可視性を検証する。テストDOMと生成WAVを使用し、ユーザーの実サービスセッションの改善完了は未認定。
